서비스를 종료하는 것은 쉬운 결정이 아닙니다.  
Lumen Insights V1을 기획하고 개발하면서 수백 시간을 쏟아부었습니다.  
채널 데이터 수집 파이프라인을 구축하고, UI를 디자인하고, 사용자들의 피드백을 반영하며 조금씩 개선해왔습니다.  

그럼에도 불구하고 저는 V1 서비스의 운영을 임시 중단하기로 결정했습니다.  
이 글은 그 결정의 배경을 솔직하게 기록한 것입니다.  

## 세 가지 치명적인 실패의 누적

V1을 종료하게 된 이유는 한 가지가 아닙니다.  
세 가지 문제가 동시에 쌓이면서 땜질로는 더 이상 해결할 수 없는 지점에 도달했습니다.  

**실패 1: 아키텍처의 기반이 잘못되었다**  
V1의 모달 시스템은 각 컴포넌트가 독립적인 로컬 State로 모달을 제어하는 방식으로 구축되었습니다.  
초기에는 문제없이 보였지만, 기능이 늘어나면서 모달이 겹치고, 뒤로가기가 오작동하고, 스크롤이 잠기는 문제가 연쇄적으로 발생했습니다.  
이것은 패치로 해결할 수 있는 수준이 아니었습니다.  
아키텍처 자체를 갈아엎어야만 했습니다.  

**실패 2: UX 부채가 임계치를 넘었다**  
데이터가 폭증하면서 메모리 누수가 발생했고, 대시보드 로딩 시간이 점점 늘어났습니다.  
모달이 열렸을 때 배경 스크롤이 막히지 않아 화면이 흔들리는 현상, 인앱 플레이어를 띄웠을 때 배경의 다른 영상 iframe이 동시에 재생되어 소리가 겹치는 문제도 있었습니다.  
사용자 입장에서는 "이 서비스는 왜 이렇게 버벅거리지?"라는 인상이 남을 수밖에 없었습니다.  

**실패 3: 수익화 전략이 구조적으로 막혔다**  
구글 애드센스 승인을 위해 여러 번 심사를 요청했지만 "가치 있는 콘텐츠 부족"이라는 이유로 반복 거절당했습니다.  
SaaS 대시보드 구조상 텍스트 콘텐츠가 부족하여 구글 봇이 사이트를 제대로 읽지 못한다는 것을 뒤늦게 깨달았습니다.  
수익 없이 서버 비용만 나가는 상황이 지속될 수는 없었습니다.  

## "개선"이 아닌 "재건"을 선택한 이유

이 세 가지 문제를 인식했을 때, 저는 두 가지 선택지 앞에 서있었습니다.  

**선택지 A**: V1을 유지하면서 문제들을 하나씩 패치한다.  
**선택지 B**: V1을 종료하고 처음부터 올바른 아키텍처로 V2를 개발한다.  

선택지 A를 선택하면 단기적으로는 서비스가 유지됩니다.  
하지만 잘못된 기반 위에 계속 쌓아올리는 것은, 기울어진 건물을 안에서 계속 인테리어하는 것과 같습니다.  
결국 더 큰 붕괴가 기다리고 있습니다.  

저는 선택지 B를 선택했습니다.  
단기적인 서비스 중단은 피할 수 없지만, 올바른 기반 위에 만들어진 V2가 장기적으로 훨씬 더 나은 서비스가 될 것이라는 확신이 있었기 때문입니다.  

## V2에서 달라지는 것들

V2는 단순히 V1에 기능을 추가한 업그레이드가 아닙니다.  
세 가지 실패를 교훈 삼아 처음부터 다시 설계한 완전히 다른 서비스입니다.  

| 영역 | V1 (실패한 방식) | V2 (바로잡는 방식) |
|---|---|---|
| 모달 아키텍처 | 로컬 State 분산 관리 | 100% URL 파라미터 중앙 통제 |
| 수익화 | SaaS 앱에 직접 광고 삽입 | 독립 블로그 + 프로그래매틱 SEO |
| 보안 | 인증 가드 불완전, 쿠키 설정 오류 | 3단계 권한 매트릭스 + 감사 완료 |
| 데이터 | API 한계 숨김, 화면 채우기용 데이터 | 실측/추정 명확히 분리, 투명 공개 |

V2는 넷플릭스 스타일의 전체화면 모달, URL 딥링킹, ShortsPlayer iframe 충돌 해결, 전면 접근 제어 시스템을 갖추고 태어났습니다.  

## 실패를 인정하는 것이 성장의 출발점이다

이 글을 쓰면서 V1이 완전한 실패는 아니었다는 것을 알고 있습니다.  
V1이 없었다면 어떤 아키텍처가 문제를 일으키는지, 어떤 수익화 전략이 구조적으로 막히는지 직접 경험하지 못했을 것입니다.  
그리고 그 경험이 V2를 처음부터 더 올바르게 설계할 수 있게 해주었습니다.  

스타트업 세계에서 "빠른 실패(Fail Fast)"는 전략입니다.  
V1의 실패를 빨리 인정하고 V2로 전진하는 것이, 실패를 인정하지 못하고 잘못된 서비스를 계속 끌고 가는 것보다 훨씬 나은 선택입니다.  

[Lumen Insights V2](https://app.lumeninsights.kr/?utm_source=lumen_blog&utm_medium=blog_post&utm_campaign=auto_generated_post)는 V1의 모든 실패를 교훈으로 삼아 만들어진 서비스입니다.  
아직 완벽하지 않습니다. 여전히 매일 버그를 발견하고 고칩니다.  
하지만 이번에는 올바른 기반 위에 서 있습니다.  
그것이 가장 중요한 차이입니다.
