## 새벽 2시에 날아온 클라우드 요금 경고

클라우드 인프라를 사용하는 서비스를 운영하다 보면 어느 날 갑자기 예상치 못한 청구서를 받는 경험을 할 수 있습니다.  
악성 봇이 API 엔드포인트를 무차별로 호출하거나, DDoS(분산 서비스 거부) 공격이 발생하면 서버 리소스 사용량이 폭발적으로 증가하고, 그 결과는 수백만 원의 클라우드 청구서로 돌아옵니다.  

1인 개발자는 대기업과 달리 전담 보안팀이 없습니다.  
코드를 작성하고, 마케팅을 하고, 고객 지원까지 혼자 처리하는 상황에서 보안은 종종 뒷전으로 밀리기 쉽습니다.  
그러나 보안 사고는 '운이 없으면 당하는 것'이 아니라, **준비되지 않으면 당하는 것**입니다.  

이 글에서는 1인 개발자가 최소한의 비용으로 서비스를 보호할 수 있는 실전 방어 전략을 단계별로 정리합니다.  

## 소규모 SaaS를 노리는 흔한 공격 패턴

소규모 SaaS 서비스를 대상으로 한 보안 위협 유형별 발생 빈도를 분석한 결과입니다.  

| 공격 유형 | 발생 빈도 | 잠재적 피해 | 방어 난이도 |
|---|---|---|---|
| 자격증명 스터핑 (무차별 로그인 시도) | 매우 높음 | 계정 탈취 | 낮음 (Rate Limiting으로 방어) |
| API 키 스크래핑 | 높음 | 요금 폭탄 | 중간 |
| 크롤링 봇 과부하 | 높음 | 서버 부하 및 비용 | 낮음 (robots.txt + Rate Limit) |
| SQL 인젝션 | 중간 | DB 전체 노출 | 낮음 (파라미터 바인딩) |
| DDoS 공격 | 낮음 | 서비스 다운 | 높음 (CDN 필요) |
| 민감 정보 하드코딩 노출 | 중간 | API 키/토큰 탈취 | 낮음 (환경변수 관리) |

발생 빈도가 높은 상위 3개 공격 유형은 모두 기본적인 보안 설정만으로 방어가 가능합니다.  
즉, 1인 개발자도 핵심 방어책만 제대로 구현하면 대부분의 공격을 막을 수 있습니다.  

> 보안의 파레토 법칙: 전체 공격의 80%는 20%의 기본 보안 설정만으로 방어할 수 있습니다. 완벽한 보안을 추구하기보다 핵심 방어선을 먼저 구축하는 것이 현실적입니다.

## 하루 만에 끝내는 필수 방어선 5가지

**1인 개발자를 위한 5단계 필수 보안 체크리스트**  

**방어 1: Rate Limiting (요청 속도 제한) 구현**  
API 엔드포인트에 IP 기반 요청 제한을 설정합니다.  
Node.js 환경에서는 `express-rate-limit` 라이브러리를 사용하여 분당 요청 수를 제한할 수 있습니다.  
예를 들어, 로그인 엔드포인트는 분당 5회, 일반 API는 분당 100회로 제한하는 것이 일반적입니다.  
이 설정 하나만으로 자격증명 스터핑 공격의 99%를 차단할 수 있습니다.  

**방어 2: 환경변수 관리 철저화**  
소스 코드에 API 키, 데이터베이스 비밀번호, 토큰 등 민감 정보를 절대 하드코딩하지 않습니다.  
모든 민감 정보는 `.env` 파일에 보관하고, `.gitignore`에 반드시 추가하여 버전 관리 시스템에 포함되지 않도록 합니다.  
GitHub에 실수로 API 키가 노출된 경우 유출 후 수초 내에 자동 스캔 봇이 이를 탐지하여 악용하는 사례가 실제로 빈번히 발생합니다.  

**방어 3: 클라우드 비용 알림 설정**  
AWS, GCP, Vercel 등 클라우드 플랫폼의 비용 알림 기능을 반드시 활성화합니다.  
예상 월 비용의 150%를 초과하면 즉시 이메일/SMS 알림을 받도록 설정하면 공격 발생 시 빠른 대응이 가능합니다.  
Vercel의 경우 대역폭 초과 알림, Supabase는 DB 용량 알림을 설정할 수 있습니다.  

**방어 4: Cloudflare 무료 플랜 활용**  
Cloudflare의 무료 플랜은 기본적인 DDoS 방어, 봇 차단, CDN 기능을 모두 제공합니다.  
도메인 DNS를 Cloudflare로 이전하는 것만으로 대부분의 소규모 트래픽 공격을 자동으로 차단할 수 있습니다.  
특히 악성 봇 트래픽을 선별 차단하는 'Bot Fight Mode' 기능은 무료로 사용 가능합니다.  

**방어 5: 데이터베이스 민감 컬럼 암호화**  
사용자의 이메일, 전화번호, OAuth 토큰, API 키 등 민감한 데이터는 데이터베이스에 저장 시 반드시 암호화해야 합니다.  
설령 DB가 탈취되더라도 암호화된 데이터는 즉시 악용하기 어렵습니다.  
Node.js 환경에서는 `crypto` 모듈의 AES-256-GCM 방식을 활용한 암호화 헬퍼 함수를 구현하는 것이 기본입니다.  

## 방어선 구축 후 악성 트래픽 94% 감소

Lumen Insights에서 위 5가지 방어책을 구현한 이후, 악성 봇으로 인한 API 호출이 일 평균 3,000건에서 180건으로 약 94% 감소했습니다.  
Rate Limiting 하나만으로 비정상적인 반복 요청의 대부분이 차단된 결과였습니다.  

예상치 못한 사례는 GitHub에 `.env` 파일이 실수로 커밋된 상황이었습니다.  
해당 커밋 이후 24시간도 지나지 않아 YouTube OAuth 토큰이 노출된 것을 확인했고, 즉시 토큰을 재발급하는 조치를 취했습니다.  
이 경험을 통해 `git secret` 또는 GitHub의 Secret Scanning 기능을 활성화하는 것이 얼마나 중요한지 실감했습니다.  

## 사고는 운이 없어서 당하는 게 아니다

1인 개발자에게 보안은 선택이 아닌 필수입니다.  
그러나 보안을 완벽하게 구현하려는 욕심보다, **가장 빈번한 공격을 막는 핵심 방어선을 빠르게 구축**하는 것이 현실적입니다.  
Rate Limiting, 환경변수 관리, Cloudflare 무료 플랜, 클라우드 비용 알림, DB 암호화의 5가지를 구현하는 것만으로 대부분의 소규모 서비스는 충분히 보호받을 수 있습니다.  

> 핵심 요약: 1인 개발자의 필수 보안 5가지는 Rate Limiting, 환경변수 분리, Cloudflare 무료 CDN, 클라우드 비용 알림, DB 민감 컬럼 암호화입니다. 이 5가지만으로 전체 공격의 80% 이상을 방어할 수 있습니다.
