새벽 2시에 클라우드 플랫폼에서 알림이 왔습니다. "이번 달 예상 청구 금액이 설정한 임계값을 초과했습니다."

평소 월 3~4달러 수준이던 청구 금액이 하루 만에 수십 달러를 향해 달리고 있었습니다. 로그를 열어보니 특정 IP 대역에서 API 엔드포인트를 분당 수백 회씩 두드리고 있었습니다. 자격증명 스터핑 공격이었습니다. 무차별로 아이디/패스워드 조합을 시도해서 계정을 탈취하려는 시도입니다.

그 날 밤 Rate Limiting을 급하게 추가했습니다. 분당 로그인 시도 횟수를 IP당 5회로 제한하는 설정 하나로 공격 트래픽이 즉시 99% 감소했습니다. 반나절이면 충분히 구현할 수 있는 것을 왜 미뤘는지 그때서야 후회했습니다.

## 1인 개발자가 실제로 당하는 공격 유형

거창한 해킹 기술 이야기가 아닙니다. 소규모 SaaS에서 실제로 빈번하게 발생하는 공격 유형은 생각보다 단순합니다.

| 공격 유형 | 발생 빈도 | 피해 | 방어 난이도 |
|---|---|---|---|
| 자격증명 스터핑 (무차별 로그인) | 매우 높음 | 계정 탈취 | 낮음 |
| API 키 스크래핑 | 높음 | 요금 폭탄 | 중간 |
| 크롤링 봇 과부하 | 높음 | 서버 비용 증가 | 낮음 |
| SQL 인젝션 | 중간 | DB 전체 노출 | 낮음 |
| 민감 정보 하드코딩 노출 | 중간 | API 키·토큰 탈취 | 낮음 |

상위 3개는 모두 기본 설정만으로 막을 수 있습니다. 전체 공격의 80%를 방어하는 데 화려한 보안 시스템이 필요하지 않습니다.

## 지금 당장 해야 할 5가지

**1. Rate Limiting.** 가장 먼저 해야 할 것입니다. Node.js라면 `express-rate-limit`, Nginx라면 `limit_req_zone` 설정으로 IP당 분당 요청 수를 제한합니다. 로그인 엔드포인트는 분당 5회, 일반 API는 분당 100회가 기준점입니다.

**2. `.env` 파일 절대로 커밋하지 않기.** GitHub에 API 키가 올라가면 자동 스캔 봇이 수초 내에 탐지합니다. `.gitignore`에 `.env`가 반드시 포함되어 있는지 지금 확인하세요. 혹시라도 이미 커밋했다면 키를 즉시 재발급하고 `git filter-branch`나 BFG Repo Cleaner로 이력을 제거해야 합니다.

**3. Cloudflare 무료 플랜 적용.** DNS를 Cloudflare로 이전하면 기본 DDoS 방어, 악성 봇 차단(Bot Fight Mode), CDN 기능을 모두 무료로 사용할 수 있습니다. 설정 시간 30분 미만입니다.

**4. 클라우드 비용 알림 설정.** 예상 월 비용의 150%를 초과하면 즉시 이메일 알림이 오도록 설정합니다. 공격이 발생했을 때 빠른 대응을 위한 최소한의 안전망입니다. Vercel, Supabase, AWS 모두 이 기능을 제공합니다.

**5. DB 민감 컬럼 암호화.** 사용자 이메일, 전화번호, OAuth 토큰, API 키는 데이터베이스에 저장할 때 반드시 암호화합니다. DB가 탈취되더라도 복호화 키 없이는 즉시 악용하기 어렵습니다. Node.js 기준 `crypto` 모듈의 AES-256-GCM 방식이 표준입니다.

## 사고는 '운이 없어서'가 아니다

Lumen Insights에서 이 5가지를 구현한 이후 악성 봇으로 인한 API 호출이 일 평균 3,000건에서 180건으로 94% 감소했습니다. Rate Limiting 하나만으로 이 효과가 나왔습니다.

1인 개발자에게 보안은 "나중에 할 일" 목록에 들어가기 쉽습니다. 하지만 보안 사고는 운이 없어서 당하는 것이 아니라 준비되지 않아서 당하는 것입니다. 위의 5가지는 하루 안에 전부 구현할 수 있습니다. 실제로 새벽 2시에 알림을 받는 상황이 오기 전에 해두는 것이 훨씬 낫습니다.
