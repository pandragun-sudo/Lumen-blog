Lumen Insights V1을 개발하며 수많은 AI 코딩 도구들을 거쳐왔습니다.  
초반의 놀라움은 곧 "왜 이 녀석은 어제 한 이야기를 오늘 또 잊어버리는 걸까?"라는 깊은 빡침으로 변하곤 했습니다.  
제가 안티그라비티(Antigravity) 2.0 생태계에 정착한 가장 큰 이유 중 하나는, 바로 에이전트에게 확고한 '자아'와 '기억'을 심어줄 수 있는 기능 때문이었습니다.  
오늘은 제가 독자분들께 가장 많이 받았던 질문들을 바탕으로, 1인 창업가가 AI 비서를 깐깐한 시니어 CTO로 탈바꿈시키는 **`AGENTS.md` 룰 세팅법**을 Q&A 형식으로 풀어보겠습니다.  

## Q1. AI가 자꾸 엉뚱한 코드를 짜거나 어제 정한 룰을 무시합니다. 이유가 뭔가요?

대부분의 챗봇은 '현재 열려 있는 대화창' 안에서만 기억을 유지합니다. 대화가 길어지면 과거의 기억(컨텍스트)이 창 밖으로 밀려나게 되죠.  
"이 버튼은 다크 모드로 해줘", "에러 났을 때 빈 화면 띄우지 마"라는 지시를 수백 번 해도 다음 날이면 리셋되는 이유입니다.  
이를 방지하기 위해 저는 프로젝트 최상단 폴더에 **`.agents/AGENTS.md`**라는 절대 헌법(System Prompt) 문서를 만들어 둡니다.  
안티그라비티 에이전트는 어떠한 작업을 시작하든, 심지어 새로운 대화창을 열더라도 이 파일을 0순위로 읽고 자신의 뇌 구조를 세팅합니다.  

## Q2. 그렇다면 AGENTS.md 파일에는 어떤 내용들을 적어두셨나요?

단순한 코딩 컨벤션뿐만 아니라, 저의 '개발 철학'과 '절대 금기 사항'을 하드코딩해 두었습니다.  
다음은 제가 실제로 현재 Lumen Insights 서버에서 돌리고 있는 룰의 일부 발췌본입니다.  

> **[실제 사용 중인 AGENTS.md 핵심 발췌]**
> - **아부 금지 (No Sycophancy):** 유저의 말에 무조건 동조하거나 과도한 칭찬을 하지 말 것. 리스크와 비효율성을 객관적이고 냉정하게 지적할 것.
> - **가짜 데이터 생성 금지 (Zero-Hallucination):** API 한계로 유튜브 데이터를 못 가져올 때 빈칸을 채우려고 `Math.random()` 등을 절대 쓰지 말 것. 반드시 논리적 추정치를 계산하고 '[추정 데이터]'라고 명시할 것.
> - **main 브랜치 접근 금지:** 어떠한 경우에도 main 브랜치에 다이렉트 커밋을 하지 말고, 인간이 눈으로 확인한 뒤 PR 머지(Merge)를 하도록 유도할 것.

## Q3. "아부 금지" 같은 성격적인 부분까지 룰로 정하는 이유가 있나요?

AI 특유의 "네, 알겠습니다! 훌륭한 질문입니다!" 식의 과도한 친절은 1인 창업가에게 오히려 독이 됩니다.  
제가 잘못된 방향으로 아키텍처를 설계하고 있을 때, 친절한 인턴은 "네, 그렇게 짜드릴게요!"라고 동조하지만, 깐깐한 시니어 CTO는 "그렇게 짜면 나중에 500MB DB 용량 다 찹니다. 다른 방식을 쓰시죠."라고 제동을 걸어주어야 합니다.  
저는 이 룰을 통해 저의 비즈니스를 차갑고 날카롭게 비판해 줄 '벽'을 세운 것입니다.  

## Q4. 나만의 프로젝트에 바로 적용할 방법이 있을까요?

아직 프로젝트 룰을 세팅하지 않으셨다면, 오늘 당장 워크스페이스에 `.agents/AGENTS.md` 파일을 만들고 아래의 문장을 AI에게 던져보세요.  

"나는 1인 개발로 SaaS를 만들고 있어. 네가 단순 챗봇이 아니라 깐깐한 CTO 역할을 해주길 원해. 1. 감정적 동조 배제 및 냉정한 리뷰 2. UI 원칙(이모지 금지 등) 3. 깃허브 보안 규칙(환경변수 노출 방지)을 포함해서 나만의 AGENTS.md 초안을 마크다운으로 작성해 줘."  

규칙이 명확할수록 AI는 더 넓은 자유도를 획득합니다.  
다음 에피소드에서는 "푸시해"라는 한마디로 보안 검사부터 깃허브 배포, 데이터 수집까지 끝내는 자동화의 끝판왕, **커스텀 스킬(Skill)** 파일들의 비밀을 파헤쳐 보겠습니다.
