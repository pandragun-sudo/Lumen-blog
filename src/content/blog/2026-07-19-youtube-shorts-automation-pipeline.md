cronJobs.js를 또 뜯어고친다. 유튜브 API로 데이터 긁어오는 게 뭐가 어렵냐고 호언장담했던 반년 전의 나를 패고 싶다. 매일 20개 채널을 뒤져가며 노션에 정리하던 짓거리가 진절머리 나서 자동화를 시작했는데, 그 과정이 더 진흙탕일 줄은 몰랐다.

```
[새벽 4시] 데이터 수집 레이어
  ↓ YouTube Data API v3 (quota: ~3,000 units/day)
  ↓ 채널별 최신 영상, 조회수, 좋아요 수, 댓글 수 수집
  ↓ PostgreSQL DB에 스냅샷 저장

[새벽 5시] 분석 레이어
  ↓ 전날 스냅샷 vs 오늘 스냅샷 비교 (Delta 계산)
  ↓ 24시간 조회수 증가율 상위 영상 추출
  ↓ 키워드 빈도 분석 및 트렌드 점수 계산

[아침 8시] 발행 레이어
  ↓ Gemini AI → 트렌드 데이터 기반 블로그 원고 생성
  ↓ GitHub REST API → Lumen-blog 저장소에 자동 커밋
  ↓ Cloudflare Pages CI/CD → 자동 배포
  ↓ Telegram Bot → 대표에게 완료 보고
```

API 할당량을 무시했다가 이틀 만에 계정이 막혔다. search.list가 호출 한 번에 100 유닛을 먹는 걸 알고 나서 얼마나 욕을 했는지. 좀비 크론잡도 문제였다. 2주 동안 스케줄러가 도는 척만 하고 데이터는 단 한 줄도 안 쌓였다. 헬스체크도 안 넣고 방치한 탓이다.

심지어 블로그 자동 발행과 메인 앱이 같은 Gemini API 키를 써서, 새벽에 블로그 글 찍어내느라 낮에 메인 기능이 429 에러를 뱉고 죽어버렸다. 어설프게 시스템을 엮으면 하나가 죽을 때 다 같이 죽는다. 이젠 알림 없는 시스템은 쳐다보지도 않는다. 방금 또 에러 로그가 찍혔다. 어딘가 API 리밋이 걸린 모양이다.
