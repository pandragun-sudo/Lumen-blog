개발을 하다 보면 필연적으로 반복되는 귀찮은 노동들과 마주하게 됩니다.  
깃허브(GitHub)에 코드를 푸시하기 전에 API 키가 노출되지 않았는지 매번 검사하는 일, 그리고 매일 아침 트래픽 지표를 수집하고 엑셀로 정리하는 일들이 바로 그것입니다.  
과거에는 이 모든 것을 제가 직접 챙겨야 했고, 피곤함이 극에 달한 새벽에는 기어코 대형 사고를 치고 말았습니다.  
단순한 귀찮음을 넘어 시스템의 존망을 위협했던 그날의 사건과, 이를 극복하기 위해 구축한 **'커스텀 스킬(Custom Skills)'**의 도입 과정을 시간순으로 되짚어 봅니다.  

### [사건 발생] 2026년 어느 날 새벽, 83MB의 악몽

여느 때처럼 밤샘 코딩을 마치고 잠에 들기 직전, 무심코 터미널에 `git push`를 때려 넣었습니다.  
아침에 눈을 떠서 외부 개발자의 긴급 연락을 받고 나서야 제 등골이 서늘해졌습니다.  
환경변수 파일(`.env`)과 무려 83MB짜리 운영 데이터베이스 덤프 파일이 깃허브에 평문으로 통째로 올라가 버린 것입니다.  
실제 이용자들의 데이터와 유튜브 접근 토큰들이 무방비로 노출될 뻔한 아찔한 순간이었습니다.  
수동으로 `git add`를 하고, 피곤한 눈으로 파일 목록을 대충 훑어본 인간의 필연적인 실수가 부른 참사였습니다.  

### [해결책 도입] 나만의 커스텀 스킬, auto_push의 탄생

이 사건을 계기로 저는 인간의 개입을 최소화하는 하드코어한 안전장치가 필요함을 뼈저리게 느꼈습니다.  
안티그라비티(Antigravity) 2.0에는 **스킬(Skills)**이라는 놀라운 확장 기능이 있습니다. 특정 작업에 필요한 프롬프트와 규칙들을 폴더에 묶어두고 언제든 호출할 수 있는 기능입니다.  
저는 워크스페이스 내에 `.agents/skills/auto_push/SKILL.md` 파일을 생성하고 AI에게 다음과 같은 절차를 강제했습니다.  
1. **비밀정보 검사:** 커밋할 파일 중에 API 키나 대용량 덤프 파일이 섞여 있는지 AI가 먼저 스캔한다.  
2. **브랜치 확인:** 현재 브랜치가 main이라면 작업을 즉각 중단하고, feature 브랜치를 새로 판다.  
3. **안전망 통과 후 PR 생성:** 모든 보안 검사가 끝난 뒤에만 커밋을 진행하고 깃허브 링크를 넘긴다.  

이제 저는 터미널을 열 필요 없이 캔버스 창에 **"정리해서 푸시해"**라는 한마디만 남깁니다.  
그러면 에이전트가 완벽한 보안 검열관이 되어 1~3단계를 수행하고, 저는 안전하게 머지(Merge) 버튼만 누르게 되었습니다.  

### [확장] 데이터의 늪에서 탈출하다, morning_briefing 스킬

스킬의 활용도는 단순히 깃허브 관리에만 국한되지 않습니다.  
저는 유튜브 급상승 트렌드를 분석하는 일종의 '마케터' 역할도 수행해야 했습니다. 매일 수천 개의 유튜브 쇼츠 데이터를 크롤링하고 수작업으로 지표를 필터링하는 일은 엄청난 시간 낭비였습니다.  
그래서 저는 데이터 수집을 자동화하는 `morning_briefing` 스킬을 추가로 만들었습니다.  
아침 출근길에 "오늘 브리핑해 줘"라고 입력하면, 에이전트가 백엔드 데이터베이스를 스캔하여 밤사이 터진 급상승 키워드와 트렌드 원시 데이터(Raw Data)를 텔레그램으로 깔끔하게 요약해 보내줍니다.  
데이터 수집과 필터링이라는 기계적인 노동은 철저히 AI에게 위임하고, 저는 그 데이터를 바탕으로 인사이트를 도출하고 블로그 글을 직접 써 내려가는 창조적인 업무에만 집중할 수 있게 된 것입니다.  

결과적으로 안티그라비티의 커스텀 스킬은 비개발자 출신 1인 창업가인 저에게 '시간'과 '안정성'이라는 가장 귀중한 자원을 선물해 주었습니다.  
규칙으로 AI의 성격을 잡고, 스킬로 손과 발을 달아주었다면, 이제 마지막으로 남은 것은 이 거대한 시스템이 표류하지 않도록 잡아주는 **프로젝트의 나침반**입니다.  
다음 포스팅에서는 수십 개의 채팅 세션이 바뀌어도 AI가 전체 맥락을 잊지 않게 만드는 **`PROJECT_PLAN.md`** 템플릿과 문서화의 비밀을 다루어 보겠습니다.
