## 화려한 UI 뒤에 감춰진 아키텍처의 부채

우리는 언제나 더 나은 사용자 경험을 위해 아름답고 부드러운 인터페이스를 갈망합니다.  
본 블로그에서 직접 운영 중인 유튜브 인텔리전스 서비스인 [Lumen Insights](https://app.lumeninsights.kr/?utm_source=lumen_blog&utm_medium=blog_post&utm_campaign=auto_generated_post)의 대규모 V2 리뉴얼을 진행하면서, 우리는 넷플릭스와 같은 매끄러운 다크 글래스모피즘(Dark Glassmorphism) 테마를 프로덕트 전반에 입혔습니다.  
수많은 쇼츠와 채널 데이터들이 페이지 이동의 깜빡임 없이 화면 하단에서 스르륵 솟아오르는 유려한 모달(Modal) 위에서 렌더링되도록 설계했습니다.  
초기 반응은 폭발적이었지만 이내 화려한 겉모습 뒤에 감춰져 있던 거대한 설계 결함, 일명 **모달 지옥**이 우리의 발목을 잡기 시작했습니다.  

가장 뼈아픈 문제는 사용자의 탐색 흐름이 복잡해질 때 여지없이 발생했습니다.  
쇼츠 영상들을 탐색하다가 인앱 플레이어를 띄우고, 그 안에서 다시 해당 채널의 상세 분석 모달을 열기 위해 프로필을 클릭하는 순간 화면이 기괴하게 일그러졌습니다.  
두 개의 거대한 모달 창이 겹쳐서 떠오르는 스태킹(Stacking) 버그가 터졌고, 당황한 사용자가 뒤로 가기 버튼을 누르면 모달 창이 닫히는 대신 브라우저의 이전 페이지로 튕겨 나가는 참사가 벌어졌습니다.  
아무리 아름다운 디자인을 입혀도 뼈대가 부실한 건축물은 작은 진동에도 무너지기 마련이며, 이 치명적인 결함은 프리미엄을 지향하는 서비스의 신뢰도를 바닥으로 끌어내리고 있었습니다.  

## 로컬 상태가 초래한 제어권 상실

문제의 근본적인 원인은 각 모달의 렌더링을 컴포넌트 내부의 로컬 상태인 유즈스테이트(`useState`)에 지나치게 의존하고 있었다는 점입니다.  
과거의 우리는 특정 뷰 컴포넌트 안에서 클릭 이벤트가 발생하면 임의의 상태값을 변경하여 `createPortal`이라는 리액트 함수로 모달을 강제로 띄우는 야매 방식을 남발하고 있었습니다.  
이러한 파편화된 접근 방식은 개별 컴포넌트 단위로 볼 때는 구현하기 매우 쉽지만, 전체 애플리케이션 규모가 커지면 <span style="color: #ef4444;">치명적인 상태의 파편화</span>를 초래합니다.  

시스템은 현재 화면에 몇 개의 모달이 띄워져 있는지 통합적으로 추적할 수 없게 되었습니다.  
인앱 플레이어 모달은 비디오 뷰 컴포넌트가 제어하고 채널 상세 모달은 채널 뷰 컴포넌트가 제어하다 보니, 서로 겹치지 않게 조율할 중앙 통제소인 단일 진실의 원천(Single Source of Truth)이 완벽하게 결여되어 있었던 것입니다.  
더욱 치명적인 것은 브라우저의 주소창이 모달의 상태를 전혀 알지 못한다는 점이었습니다.  
사용자의 눈앞에는 새로운 정보의 창이 열렸지만 브라우저 주소창의 URL은 단 한 글자도 변하지 않았기에, 당연히 브라우저 고유의 뒤로 가기 기능이 동작할 리 만무했습니다.  

## 100% URL 파라미터 기반 중앙 통제 아키텍처

이 처참한 설계 부채를 청산하기 위해 우리는 과감한 결단을 내렸습니다.  
모든 컴포넌트 내부에 산재해 있던 로컬 상태 변수들을 단 하나도 남김없이 전부 폐기하는 대규모 리팩토링에 착수했습니다.  
이제부터 사용자가 쇼츠 카드나 채널 썸네일을 클릭하면 모달 상태를 조작하는 대신 오직 브라우저의 주소창 URL 파라미터만 변경하도록 로직을 재설계했습니다.  
클릭 시 비디오 파라미터(`?videoId=`)나 채널 파라미터(`?channelId=`)를 URL에 추가하고 엔터를 치는 것과 완전히 동일한 동작을 수행하게 한 것입니다.  

그리고 애플리케이션 최상단에 **모달 컨트롤러(Modal Controller)**라는 강력한 관제탑 역할을 하는 단일 컴포넌트를 새롭게 배치했습니다.  
이 컨트롤러는 오직 브라우저 주소창의 파라미터 변화만을 감지하여 현재 사용자에게 어떤 모달 창을 보여주어야 하는지를 독단적이고 완벽하게 결정합니다.  
주소창에 비디오 아이디가 들어오면 기존의 모달을 부드럽게 닫고 인앱 플레이어 모달만 최우선으로 렌더링하며, 채널 아이디가 들어오면 채널 분석 모달로 즉각 스위칭합니다.  
이러한 <span style="color: #2563eb;">완전한 URL 주도(URL-Driven) 아키텍처</span> 덕분에 모든 모달의 중첩 충돌 현상은 마법처럼 완벽하게 소멸되었습니다.  

## 본질을 회복한 사용자 탐색 경험

아키텍처의 근본을 바로잡은 결과는 실로 놀라웠습니다.  
가장 큰 성과는 사용자가 브라우저의 뒤로 가기 버튼을 눌렀을 때 비로소 우리가 의도한 대로 완벽하게 작동하기 시작했다는 것입니다.  
채널 상세 모달을 열기 위해 주소창에 추가되었던 파라미터가 뒤로 가기 버튼을 통해 조용히 삭제되면서 모달 컨트롤러가 이를 인지하고 부드럽게 모달을 닫아버리기 때문입니다.  
또한 사용자가 마음에 드는 채널 분석 화면의 링크를 복사하여 지인에게 공유하거나 텔레그램 메신저로 전송하는 것도 가능해졌습니다.  
URL만 클릭하면 해당 파라미터를 읽어 들인 컨트롤러가 곧바로 채널 상세 모달을 띄워주어, 막강한 딥링킹(Deep Linking) 기능이 추가적인 개발 리소스 없이 자연스럽게 확보되었습니다.  

버그를 고치는 것에 급급해 눈앞의 코드를 덕지덕지 덧대는 땜질식 처방은 결국 더 큰 재앙을 불러오기 마련입니다.  
상태 관리의 본질은 무조건 리액트 훅을 사용하는 것이 아니라, 애플리케이션의 규모와 맥락에 맞는 **가장 신뢰할 수 있는 진실의 원천**을 찾아 위임하는 데 있습니다.  
화면의 전체적인 흐름을 바꾸는 굵직한 오버레이 창들은 브라우저 고유의 주소창이라는 훌륭한 상태 관리자에게 온전히 맡겨 보시기를 권장합니다.  
더 이상 로컬 상태의 늪에서 길을 잃지 마시고, 100% URL 파라미터가 주도하는 쾌적한 라우팅의 세계로 넘어오신다면 유려한 애니메이션과 견고한 안정성이라는 두 마리 토끼를 모두 거머쥐실 수 있을 것입니다.
