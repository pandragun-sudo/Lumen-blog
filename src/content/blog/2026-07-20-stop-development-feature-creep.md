어느 날 저는 확장 프로그램 개발 중에 갑자기 이런 생각을 했습니다.  
"폴더 분류 기능이 있으면 훨씬 편하겠는데. 그리고 태그도 있으면 좋겠고, 검색 필터도 넣으면 완벽하겠다."  
그 생각을 한 순간부터 개발은 멈췄습니다.  
멈춘 게 아니라 — 길을 잃었습니다.  

이것이 **피처 크립(Feature Creep)**이라는 괴물이 작동하는 방식입니다.  
처음에는 작은 아이디어처럼 들어오지만, 꼬리에 꼬리를 물고 기능이 불어나면서 어느새 원래 만들려던 것과 완전히 다른 무언가를 만들고 있는 자신을 발견하게 됩니다.  

## 피처 크립이 1인 창업을 죽이는 방식

대기업 개발팀에서는 피처 크립이 발생해도 누군가 브레이크를 잡아줍니다.  
PM이 "이번 스프린트 스코프 아웙"이라고 말하거나, 디자이너가 "사용자 테스트 결과 이 기능은 필요없어요"라고 데이터를 들고 옵니다.  

하지만 1인 창업가에게는 그 브레이크가 없습니다.  
내가 기획자이자 개발자이자 디자이너이기 때문에, 내 머릿속에서 나온 아이디어를 자르는 사람도 나 자신밖에 없습니다.  
그리고 대부분의 경우, 우리는 자기 자신의 아이디어에 지나치게 관대합니다.  

Lumen Insights를 개발하면서 피처 크립이 얼마나 심각한 결과를 낳는지 여러 번 경험했습니다.  

| 원래 목표 | 피처 크립 후 실제 상황 |
|---|---|
| 채널 모니터링 대시보드 | 채널 분석 + 스크랩북 + 히트맵 + 랭킹 시스템 동시 개발 시작 |
| 블로그 자동화 파이프라인 | DB 연동 + AI 생성 + GitHub 배포 + 텔레그램 알림 + 카테고리 시스템... |
| 크롬 확장 프로그램 | 메타데이터 수집 + 폴더 분류 + 태그 + 검색 + 동기화... |

공통점이 보입니까?  
모두 처음에는 단순한 목표로 시작했지만, 개발하면서 "이것도 있으면 좋겠는데"를 반복한 결과입니다.  
그리고 이 중 절반은 출시가 지연되거나 아예 폐기되었습니다.  

## 80% 완성에서 멈추는 판단력

피처 크립을 막는 데 있어 제가 스스로 설정한 기준은 하나입니다.  

> **"지금 이 기능 없이도 사용자가 핵심 문제를 해결할 수 있는가?"**

대답이 "예스"라면 개발을 멈춥니다.  

Lumen Shorts Swipe-File 크롬 확장 프로그램을 만들 때, 폴더 분류 기능 개발에 착수하려던 순간 이 질문을 던졌습니다.  
"지금 이 기능 없이도 쇼츠 레퍼런스를 저장하고 나중에 꺼내볼 수 있는가?"  
대답은 "예스"였습니다.  
저는 폴더 분류 기능 개발을 즉시 중단했습니다.  

이것은 완성도를 포기하는 것이 아닙니다.  
**80%로 완성된 도구를 지금 당장 사용자에게 전달하는 것이, 120%로 완성된 도구를 6개월 후에 전달하는 것보다 훨씬 가치 있다**는 판단입니다.  

## 피처 크립을 방어하는 3가지 실전 방법

## 기능 아이디어를 즉시 백로그에 넣고 잊기

좋은 아이디어가 떠오르면 메모하고, 즉시 개발하지 않습니다.  
저는 `PROJECT_PLAN.md`의 "Backlog" 섹션에 적어두고 최소 1주일 후에 다시 봅니다.  
1주일 후에도 여전히 중요해 보이면 그때 우선순위를 검토합니다.  
놀랍게도 백로그에 적은 아이디어의 70%는 1주일 후에 다시 봤을 때 "굳이 안 해도 되겠다"는 결론이 납니다.  

## "이 기능이 없어서 사용자가 이탈했는가?" 확인하기

기능을 추가하고 싶다면, 먼저 그 기능이 없어서 실제로 문제가 생겼는지 확인해야 합니다.  
가상의 불편함을 해결하기 위해 개발하는 것은 피처 크립의 가장 흔한 형태입니다.  
실제 사용자 피드백이 없다면, 그것은 내 상상 속의 문제일 가능성이 높습니다.  

## 개발 시작 전 완성 기준(Definition of Done) 명시하기

개발을 시작하기 전에 "이 기능이 완성되는 조건"을 미리 적어두세요.  
예: "영상 URL, 채널명, 조회수를 저장하고 목록으로 볼 수 있으면 완성이다."  
이 조건이 충족되면 개발을 멈추고 배포하는 것이 규칙입니다.  
사전에 완성 기준을 적어두지 않으면, 완성의 기준은 항상 현재 상태보다 조금 앞에 있게 됩니다.  

## 멈추는 것이 더 빠른 길이다

지금 Lumen Insights는 처음 기획했던 것보다 훨씬 적은 기능을 가지고 있습니다.  
하지만 그 덕분에 지금 이 순간 작동하고 있습니다.  
만약 처음 머릿속에 그렸던 모든 기능을 다 만들려 했다면, 아직도 개발 중이었을 것입니다.  

완벽한 도구는 존재하지 않습니다.  
80%의 완성도로 세상에 내놓고 사용자의 반응을 보며 진화하는 것이, 완벽을 추구하다 결코 세상에 나오지 못하는 것보다 압도적으로 낫습니다.  
Lumen Insights도 그렇게 지금 여기까지 왔습니다.  
다음에 기능을 추가하고 싶다는 생각이 들 때, 한 번만 멈추고 물어보세요.  
"지금 이것 없이도 되는가?"
