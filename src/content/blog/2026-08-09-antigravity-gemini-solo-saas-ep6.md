SaaS(서비스형 소프트웨어)를 운영하다 보면 트래픽의 증가와 함께 기뻐할 일만 생기는 것은 아닙니다. 트래픽이 늘어날수록 시스템의 틈새를 파고들어 부당한 이득을 취하려는 '어뷰징(Abusing)' 공격 또한 필연적으로 증가합니다. 
초기에는 선의의 사용자들만 있을 것이라 믿고 방어 코드를 짜지 않았지만, API 할당량을 비정상적으로 소모하거나 계정을 공유하는 사례가 발견되면서 저는 단호한 결단을 내렸습니다. 
오늘은 Lumen Insights를 지키기 위해 구축한 3단계의 철통같은 보안 방어선 구축기를 소개합니다.

## 1단계: 개발자 도구(DevTools) 원천 차단

가장 먼저 도입한 것은 브라우저의 개발자 도구를 원천적으로 차단하는 스크립트였습니다. 
악의적인 사용자가 개발자 도구를 열어 API 엔드포인트를 탈취하거나, 소스 코드를 뜯어보는 행위를 막기 위함이었습니다. 단순히 우클릭과 F12 단축키를 막는 수준을 넘어섰습니다.
500ms 간격으로 `debugger` 구문을 실행하여 개발자 도구가 열리는 즉시 페이지의 렌더링을 멈추고 빈 화면으로 강제 전환시키는 하드코어한 방식을 적용했습니다.
더 나아가, 개발자 도구가 열렸다는 이벤트가 감지되는 순간 즉시 백엔드 `/api/user/devtools-report`로 신호를 보내 데이터베이스에 해당 IP와 유저 정보를 로깅합니다. 즉, 문을 따려는 시도 자체를 기록으로 남겨 잠재적 해커를 색출해 내는 것입니다.

## 2단계: 계정 동시 접속 킥아웃 (Kickout) 시스템

넷플릭스와 같은 거대 플랫폼에서도 골머리를 앓는 '계정 공유' 문제를 방지하기 위해 중복 로그인 방지 로직을 신설했습니다.
사용자가 구글 로그인을 시도할 때마다 고유한 `UUID`를 발급하여, 이를 세션과 데이터베이스(`current_session_id`)에 동시에 동기화합니다.
만약 누군가 다른 기기나 브라우저에서 동일한 계정으로 접속하여 새로운 세션을 발급받게 되면, 데이터베이스의 세션 ID가 교체됩니다. 
기존에 접속해 있던 사용자는 다음 API 요청을 날릴 때 세션 ID 불일치 오류(401 Unauthorized)를 반환받고 시스템에서 강제로 로그아웃(Kickout)됩니다. 이 깔끔한 로직 하나로 무분별한 계정 돌려쓰기와 수익 누수를 완벽하게 차단했습니다.

## 3단계: 검색 폭주 감지와 텔레그램 직통 알림

매크로나 크롤러 봇에 의한 비정상적인 검색 폭주는 API 쿼터를 고갈시키는 주범입니다. 
이를 막기 위해 사용자의 일일 검색 횟수(`daily_search_count`)를 트래킹하여 50, 100, 200, 500회 등 특정 임계점에 도달할 때마다 텔레그램 봇이 관리자(저)에게 실시간으로 경고 알림을 발송하도록 설계했습니다.
단순히 알림에서 끝나는 것이 아닙니다. 이상 징후가 확실하다고 판단되는 봇 계정은 텔레그램에서 즉시 명령어를 날려 계정을 차단(Ban)시키거나 티어를 강등시킬 수 있습니다.

보안은 마치 창과 방패의 싸움과도 같습니다. 공격자는 끊임없이 새로운 빈틈을 찾을 것이고, 방어자는 이를 틀어막아야 합니다. 
하지만 이렇게 촘촘히 엮어둔 방어선 덕분에, 저는 서버 요금 폭탄이나 데이터 유출의 공포에서 벗어나 안심하고 숙면을 취할 수 있게 되었습니다.
