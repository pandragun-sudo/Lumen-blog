서버 API 쿼터는 이미 바닥을 드러냈고 화면 모달은 겹겹이 증식하는 기괴한 버그를 뿜어내고 있었다. 블로그 포스팅 마감일은 코앞이다. 1인 개발을 하다 보면 머릿속이 새하얗게 타버리는 엔트로피 폭발의 순간이 주기적으로 찾아온다. 

감정을 섞지 않고 기계의 인지 과정을 훔쳐오기로 했다. 문제 정의, 증거 수집, 해결책 모색, 검증, 기록.
API가 먹통이라는 건 현상일 뿐 문제가 아니다. YouTube Data API 일일 할당량 1만 유닛이 오전 11시에 증발하는 것, 그리고 데이터 수집 범위를 훼손하지 않고 소모량을 5천 이하로 압축하는 것이 진짜 문제다. 범위를 이렇게 좁혀야만 손을 댈 수 있다.

곧바로 서버 로그를 뒤졌다. 느낌이나 감 따위는 배제하고 무식하게 집계했다. search.list 엔드포인트가 전체 쿼터의 30%를 혼자 집어삼키고 있었다. 
대안은 뻔했다. 호출을 반토막 내거나 수집 주기를 48시간으로 늘려 서비스 품질을 박살 내는 것. 아니면 search.list를 아예 DB 캐시 조회로 대체하는 것. 
품질 유지와 비용 절감의 교차점은 캐시 전환뿐이었다. 스테이징 환경에서 24시간을 돌렸다. 소모량 3,200 유닛. 목표치 달성. 

모든 과정은 `PROJECT_PLAN.md`에 건조하게 기록했다. 일일 소모 1만에서 3천2백으로 감소. 신규 채널 발굴 시에는 여전히 API가 필요하다는 잔여 리스크까지 모조리 적어뒀다.

1인 창업자는 혼자서 PM, 개발자, QA 역할을 다 쪼개서 수행해야 한다. 가장 역겨운 단계는 증거 수집이다. 데이터가 없으면 본능적으로 뇌피셜을 굴려서 빈칸을 채우려고 든다. 알 수 없는 건 알 수 없다고 인정해야 한다.
