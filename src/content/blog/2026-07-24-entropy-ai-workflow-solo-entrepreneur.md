Lumen Insights를 혼자 개발하던 어느 날, 저는 동시에 세 가지 문제 앞에 놓여 있었습니다.  
서버 API 쿼터가 고갈되어 데이터 수집이 멈췄고, 프론트엔드에서 모달 중첩 버그가 터졌으며, 다음 주 블로그 포스팅 일정은 비어있었습니다.  
어디서부터 손을 대야 할지 모르는 이 상태 — 1인 창업가라면 누구나 경험하는, 무질서도(Entropy)가 최고조에 달한 순간입니다.  

이 순간 저를 구해준 것은 놀랍게도 AI가 문제를 처리하는 방식에 대한 관찰이었습니다.  
최고 성능의 AI 모델들이 복잡한 요청을 받았을 때 내부적으로 수행하는 5단계 인지 과정을 그대로 인간의 업무 프로세스에 이식할 수 있다면 어떨까?  
이 발상이 저의 업무 방식을 근본적으로 바꿨습니다.  

## AI의 5단계 인지 프레임워크

최고 성능의 AI가 복잡한 프롬프트를 처리할 때 거치는 단계를 단순화하면 다음과 같습니다.  

```
1. Scope    → 무엇을 해결해야 하는가? 범위를 명확히 정의한다.
2. Evidence → 판단의 근거가 되는 사실은 무엇인가? 데이터를 수집한다.
3. Solve    → 여러 대안 중 최선의 해결책을 선택하고 이유를 기록한다.
4. Verify   → 해결책이 처음 정의한 목표를 충족하는가? 스스로 검증한다.
5. Report   → 결론을 명확하게 전달하고 불확실성을 투명하게 밝힌다.
```

이것을 1인 창업 업무에 그대로 적용하면 어떻게 될까요?  

## 실전 적용: 서버 API 쿼터 고갈 문제

앞서 언급했던 그날의 세 가지 문제 중 가장 시급한 "API 쿼터 고갈"을 이 프레임워크로 해결한 과정입니다.  

**1단계 - Scope (범위 정의)**  
막연하게 "API가 문제다"라고 생각하지 않고, 구체적으로 정의했습니다.  
"YouTube Data API 일일 할당량 10,000 units가 오전 11시에 소진되어 새벽 수집 크론잡이 실패하고 있다. 해결 목표: 동일한 데이터 수집 범위를 유지하면서 일일 사용량을 5,000 units 이하로 줄인다."  

**2단계 - Evidence (증거 수집)**  
감이 아니라 실제 데이터를 봅니다.  
서버 로그에서 API 호출별 units 소모량을 집계했습니다.  

| API 엔드포인트 | 일일 호출 수 | 소모 Units |
|---|---|---|
| `search.list` | 30회 | 3,000 units (30%) |
| `videos.list` | 500회 | 500 units (5%) |
| `channels.list` | 200회 | 200 units (2%) |
| `commentThreads.list` | 630회 | 630 units (6%) |

문제가 명확해졌습니다. `search.list`가 전체 소모량의 30%를 차지하고 있었습니다.  

**3단계 - Solve (해결책 선택)**  
여러 대안을 검토했습니다.  
- 안 A: 모든 API 호출을 절반으로 줄인다 → 수집 데이터 양 감소, 서비스 품질 저하
- 안 B: `search.list`를 DB에 캐시된 채널 ID 조회로 대체한다 → 품질 유지, 비용 90% 절감
- 안 C: 수집 주기를 24시간에서 48시간으로 늘린다 → 데이터 신선도 감소

안 B를 선택했습니다. 이유: 데이터 품질 유지 + 비용 절감 효과 최대.  

**4단계 - Verify (검증)**  
코드를 배포하기 전, 스테이징 환경에서 24시간 시뮬레이션을 돌렸습니다.  
예상 소모량: 약 3,200 units. 기존 대비 68% 절감. 목표 5,000 units 이하 달성 확인.  

**5단계 - Report (보고)**  
결과를 `PROJECT_PLAN.md`에 기록했습니다.  
"2026-07-24: search.list → DB 캐시 전환으로 일일 소모 10,000 → 3,200 units 감소. 잔여 불확실성: 신규 채널 발굴 시에는 여전히 search.list 필요, 월 5회 이하로 제한."  

## 이 프레임워크가 1인 창업에서 특히 강력한 이유

대기업에서는 이 5단계가 여러 사람 사이에서 자연스럽게 분산됩니다.  
PM이 Scope를 정하고, 데이터팀이 Evidence를 수집하고, 개발팀이 Solve하고, QA팀이 Verify합니다.  

하지만 1인 창업가는 이 모든 역할을 혼자 수행해야 합니다.  
그렇기 때문에 이 5단계를 의식적으로 순서대로 밟아가는 것이 더욱 중요합니다.  
단계를 건너뛰는 순간, 가장 흔하게 벌어지는 일은 Scope도 제대로 정의하지 않은 채 Solve로 직행하는 것입니다.  
이것이 1인 창업가가 같은 문제를 반복해서 해결하게 되는 가장 큰 이유입니다.  

## 불확실성을 정직하게 다루는 법

이 프레임워크에서 가장 어려운 단계는 **Evidence**입니다.  
충분한 데이터가 없을 때, 우리는 추측으로 그 빈자리를 채우려는 강한 충동을 느낍니다.  

하지만 AI가 증거 없이 답하지 않듯, 1인 창업가도 데이터 없이 결론 내리는 것을 경계해야 합니다.  
데이터가 없다면 "현재로서는 알 수 없다"고 인정하고, 그 불확실성을 기록하는 것이 잘못된 판단을 내리는 것보다 훨씬 낫습니다.  

Lumen Insights의 모든 기능 기획과 버그 수정은 이 5단계 프레임워크를 통해 처리됩니다.  
복잡해 보이는 문제도 이 순서를 지키면 반드시 실마리가 보입니다.  
혼란스러운 상황에서 가장 먼저 할 일은 해결책을 찾는 것이 아니라, 정확히 무엇이 문제인지 정의하는 것임을 잊지 마세요.
